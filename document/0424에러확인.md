## 결론 요약

- **코드 구조상 충돌·덮어쓰기가 가능한 분기는 확실히 존재함** (5건)

- 사용자 직감("그룹 단위로 묶을 때 충돌 가능한 구조") 자체는 **정확**함.

## 🔴 #1. `calculateDailyProfitRows` Step 4 — 그룹키 충돌로 인한 덮어쓰기

**파일**: `apps/backend/src/helpers.ts:802-820`

```ts
const resultMap = new Map<...>();
groupRowMap.forEach((groupRow, groupKey) => {
  resultMap.set(groupKey, groupRow);          // ① 자식 롤업된 부모 행
});
childRowMap.forEach((childRow, childKey) => {
  const unit = salesUnitsById.get(childRow.canonicalSalesUnitId);
  if (!unit?.parentSalesUnitId) {
    resultMap.set(childKey, childRow);        // ② 같은 키면 ①을 덮어씀
  }
});
```

**키 형식**: 양쪽 다 `${date}:${unitId}` → 동일.

**충돌 시나리오**:
- (A) `order_item.canonicalSalesUnitId`가 그룹 부모 ID로 직접 매핑된 경우
  → Step 1: `childRowMap[date:G]`에 부모 직접 매출 적재
  → Step 2: `groupRowMap[date:G]`에 자식 롤업 적재
  → Step 4: ②가 ①을 덮어씀 → **자식 롤업 매출 손실**
- (B) 단독 유닛(`isGroup=false`)에 자식이 매달린 비정상 데이터
  → Step 2가 단독 부모 키에 자식 롤업 적재 (line 726에서 `parentRow.isGroup = true` 강제 변조)
  → Step 3에서 부모 단독 광고비가 `childRowMap[date:G]`에 적재
  → Step 4 충돌 → 손실

**증상**: "어떤 행이 통째로 사라지거나, 부모 행에 광고비만 남고 매출이 비거나, 합이 안 맞음"

**검증 SQL**:
```sql
-- (A) order_items가 그룹 부모를 직접 가리킴
SELECT oi.id, oi.payload->>'canonicalSalesUnitId' as unit_id,
       csu.payload->>'displayName' as name,
       csu.payload->>'isGroup' as is_group
FROM order_items oi
JOIN canonical_sales_units csu ON csu.id = oi.payload->>'canonicalSalesUnitId'
WHERE (csu.payload->>'isGroup')::boolean = true;

-- (B) parentSalesUnitId가 단독 유닛을 가리키는 비정상
SELECT c.id as child_id, p.id as parent_id,
       p.payload->>'isGroup' as parent_isGroup
FROM canonical_sales_units c
JOIN canonical_sales_units p ON p.id = c.payload->>'parentSalesUnitId'
WHERE (p.payload->>'isGroup')::boolean = false;
```

## 🔴 #2. `getActiveSalesUnitsForIdMapping`에 `isGroup` 필터 누락

**파일**: `apps/backend/src/sales-unit-auto-mapper.ts:104-113`

```ts
export const getActiveSalesUnitsForIdMapping = (database, storeId) =>
  database.canonicalSalesUnits.filter(
    (item) => item.storeId === storeId && item.isActive && (
      (item.linkedOptionCodes?.length > 0) ||
      (item.linkedProductIds?.length > 0)  ||
      (item.linkedManageCodes?.length > 0)
    ),  // ← !item.isGroup 빠짐
  );
```

**문제**:
- 자식·단독만 거르는 `getActiveSalesUnitsForAutoMapping`(line 101)과 달리 `isGroup` 가드 없음
- line 205-212에서 `manageCodeMap.set(code, unit.id)` — 같은 코드를 다른 unit이 이미 가지고 있으면 **조용히 덮어씀**
- 그룹 부모와 자식이 동일 manageCode/optionCode/productId를 가지면 **데이터 순서에 따라 부모 또는 자식으로 매핑됨 (불안정)**
- 부모로 매핑된 경우 → 위 #1 시나리오(A)를 그대로 트리거

**검증 SQL**:
```sql
-- 같은 manageCode를 여러 unit이 가지는 경우
SELECT manage_code, COUNT(*),
       STRING_AGG(id || '(' || (payload->>'isGroup') || ')', ', ')
FROM canonical_sales_units, jsonb_array_elements_text(payload->'linkedManageCodes') AS manage_code
GROUP BY manage_code HAVING COUNT(*) > 1;

-- linkedOptionCodes
SELECT option_code, COUNT(*) FROM canonical_sales_units,
       jsonb_array_elements_text(payload->'linkedOptionCodes') AS option_code
GROUP BY option_code HAVING COUNT(*) > 1;

-- linkedProductIds
SELECT product_id, COUNT(*) FROM canonical_sales_units,
       jsonb_array_elements_text(payload->'linkedProductIds') AS product_id
GROUP BY product_id HAVING COUNT(*) > 1;
```

## 🟠 #3. `seedDefaultCampaignMappingsForStore` 멱등 체크가 snapshot 기준

**파일**: `apps/backend/src/campaign-mapping.service.ts:52-140` (특히 73-86)

```ts
const snapshot = this.databaseService.getSnapshot();   // 라이브 reference
for (const pattern of defaultPatterns) {
  const existing = snapshot.campaignMappings.find(...);  // snapshot만 검사
  if (existing) continue;
  draft.campaignMappings.push({ id: createId(), ... });   // draft에만 push
}
```

**문제**:
- 0416 timeout 수정 이후 snapshot은 deep-clone 안 되는 라이브 reference (메모리 `project_timeout_fix_0416.md`)
- 같은 트랜잭션 내에서 두 번 호출되거나 모듈 hot-reload 시 → draft에 push 됐지만 snapshot 검사는 통과 → **같은 패턴이 두 번 적재**
- 중복된 매핑 → `evaluateAdMapping`(`ad-mapping-engine.ts:218-226`)에서 `matches.length > 1` → `MULTIPLE_RULES → null`
- **결과: 광고비가 중복 합산이 아니라 통째로 unmapped로 사라짐**

**증상**: "광고비가 갑자기 모자라거나 사라짐" (중복 집계 반대 방향이지만 데이터 신뢰성 문제)

**검증 SQL**:
```sql
SELECT payload->>'storeId' as store_id,
       payload->>'normalizedCampaignPattern' as pattern,
       COUNT(*)
FROM campaign_mappings
WHERE (payload->>'isActive')::boolean = true
GROUP BY 1, 2
HAVING COUNT(*) > 1;
```

## 🟡 #5. 자식 ID 광고비 → 부모 단독으로 승격되어 다른 행과 합쳐짐

```ts
let targetUnit = rawUnit;
if (rawUnit.parentSalesUnitId) {
  const parentUnit = salesUnitsById.get(rawUnit.parentSalesUnitId);
  if (parentUnit) { targetUnitId = parentUnit.id; targetUnit = parentUnit; }

if (targetUnit.isGroup) { groupRowMap... }
```

**문제**:
- 자식이 단독 부모를 갖는 비정상 데이터에서, 자식 ID로 매핑된 광고비가 부모 단독 행으로 흡수
- 부모 단독에 자체 매출이 있으면 그 행에 자식 광고비가 더해짐
- 부모 입장에서 "내가 안 쓴 광고비가 잡힘" → **사용자가 "중복 집계"로 인식할 가능성 높음**

## 🟡 #6. 광고 매핑 부모 승격이 두 곳에서 이중 처리

**파일**: `ad-mapping-engine.ts:165-175` + `helpers.ts:759-765`

- 정상 데이터에서는 idempotent. 그러나:
  - 레거시 데이터 (recalculate 이전 적재된 ad)

**중대한 버그라기보다 Source of Truth가 두 군데에 있어 디버깅이 매우 어려운 구조**.
